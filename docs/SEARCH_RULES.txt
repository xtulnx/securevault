SecureVault 检索匹配与排序规则

匹配范围
保留原有 AND 语义：每个查询条件都必须命中。支持普通包含、字段限定、精确值（=）、前缀（^）、后缀（$）及正则（~）。排序不扩大检索范围、不自动模糊纠错，也不改变精确过滤语义。
目录、环境、数据集及应用访问权限先限定候选记录。主表和附表仅已公开的索引/展示字段参与匹配，普通、隐藏、敏感、忽略字段不参与排序。

按以下优先级依次比较
1. 普通多关键词查询，优先某个公开字段的完整值等于整条短语。例如 alpha beta 优先字段值 alpha beta；带字段名、正则或显式操作符的 AND 条件不合成为短语。
2. 比较每个条件最好的命中程度：完整字段值 > 完整词段 > 前缀或后缀 > 内部局部包含。多条件先比较最弱命中，再比较其余条件，避免某个条件匹配极好而另一个只擦边的记录抢到前面。
   完整词段以值边缘、标点或空白为界，字母、数字及下划线属于词内字符。例如 cat 等于完整值；cat-food 包含完整词段；catnap / bobcat 为前后缀；bobcatfish 为内部包含。连续中文字符不会被误判为分隔的词段。
3. 上述程度相同时，关键词集中命中同一个公开字段的记录优先。
4. 再比较命中字段的业务作用：公开逻辑 KEY 字段 > 配置的记录标识字段 > 主表索引字段 > 主表展示字段 > 附表公开字段 > 目录或环境标签。完整匹配始终先于仅局部命中的 KEY；不假定字段名一定为 name。
5. 再比较命中片段占字段值的比例，优先更紧凑的值。同一关键词重复出现不额外加分，同一查询条件重复输入也不加分，字段数量多不自动提高排名。
6. 最后依次比较有效记录优先、更新时间从新到旧、系统 ID 从小到大，保证同一数据快照下顺序稳定。没有文本查询或仅有目录/环境/数据集条件时使用此顺序。

筛选与特殊值
显式 category、env/environment、dataset/dataset_id 条件只限定范围，不参与匹配度计算。category:=父目录 仍包含子目录。附表支持 supplement. / 附表. 命名空间；显式主表限定不会被同名附表字段代替。
精确匹配保持现有 ASCII 大小写不敏感语义；包含、前后缀使用现有小写比较。数字 0、布尔 false 可作为实际值匹配。
正则使用服务端实际命中片段判断完整值、边界和覆盖比例；不把正则表达式本身当关键词，也不在浏览器重跑正则。零宽命中不会被判成完整值匹配。

输出与分页
在整个已授权范围计算匹配度并统计总数，使用前 K 条选取获得与全排序一致的当前页，所有客户端和 API 使用同一顺序；总数不变。K 为分页偏移量加每页条数，第一页仅保留一页候选。同一记录的命中字段也按匹配程度、条件集中度、业务作用和覆盖比例排列，主表与附表可交错前置，其余字段保持数据集的配置顺序。高亮只使用实际匹配片段，不制造新的命中。
分页期间如果数据被修改，结果仍可能移动；本规则保证未修改数据的稳定顺序，不提供跨请求快照。

实现与验证
服务端：server/src/search_rank.rs；过滤候选与排序共用 main.rs 的字段解析规则。
测试覆盖完整值/词段/前后缀/包含、多关键词、字段权重、目录筛选、附表命名空间、中文、正则、0/false、重复条件、排序并列、分页及高亮。
优化前实现作为独立测试基准保留，逐项验证总数、字段、顺序、高亮与元数据相等。性能方法、测量结果与复现命令见 docs/SEARCH_PERFORMANCE.txt。
