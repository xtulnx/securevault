SecureVault 数据集交换格式 · v1

用途
“仅结构”用于复制数据集定义并创建空数据集，类似导出表结构；“仅数据”保留 JSON/JSONL/CSV/XLSX/YAML/TOML 常规交换；“结构与数据”使用原生 JSON 数据集包。全量加密保险库备份仍使用 BACKUP_FORMAT.md 中的独立格式。

原生 JSON 顶层
format: securevault-dataset
version: 1
mode: schema 或 package
record_scope: all 或 active
schema: 数据集定义
records: 主表记录数组
supplements: 附表记录数组
templates: 可选导入映射模板数组

schema 可选携带 name（数据集显示名称，最多 120 个字符，空字符串表示随目录末级名称显示）；旧包省略 name 时，新建实例使用空名称，导入已有实例保留原名称；显式提供 name 的更新会在确认前列出名称变化。schema 保留 category_path、environment（兼容第一个标签）、environments（全部标签名称数组，可选）、description（完整 Markdown）、fields、identity_fields、conflict_strategy、list_fields、display_config、supplement_fields、supplement_link_version。
schema 可选携带 schema_name（模型名称）与 schema_description（模型说明，Markdown 原文）。新建导入保留模型说明；导入现有数据集不会用来源说明覆盖其共享模型说明。新建导入保留模型名称及全部标签；旧文件的 customer 名称转成额外标签。标签按名称复用或新建，未修改兼容 environment 字段时保留原文件中的全部标签。导入请求可用 environments 数组整体设置标签；旧单 environment 字段修改表示单标签覆盖。不按名称自动合并数据模型，每次新建导入仍创建独立模型，需在管理界面手动合并。已有字段的结构变更不能绕过模型发布：若现有结构被多个实例引用且有差异，拒绝本次导入，需先在数据模型管理中预览并发布。
fields 保留 source_key、display_name、zone、unique、position。display_config.identifier_fields 只能引用索引或展示字段，density 为 summary 或 full。记录标识不等同于逻辑唯一 KEY。

记录
主表为 source_id、values、omitted_fields、expired；附表还包含 main_source_id、orphan、link。values 保留 JSON 类型，业务字段 id 与系统 ID 分开处理。缺失值不写入 values，JSON null 仍是实际值。
默认省略敏感和隐藏字段，将实际省略项列入 omitted_fields，不写入掩码。更新现有记录时省略的值保留，明确传入的值参与更新。导入重新分配系统 ID、重建加密值并映射附表关联，不迁移应用凭据、数据库密钥或会话。
active 包只包含有效主记录及对应附表，并保留失联附表；all 包还包含过期记录及过期标记。

API
GET /datasets/{id}/export?content=schema|package&format=json
include_templates、include_supplements、include_secrets 默认 false；include_expired 默认 true。
content=data（或省略）沿用常规格式导出。原生结构与包只允许管理会话。
POST /datasets/transfer/preview
POST /datasets/transfer/import
请求包含 package、category_path、可选 environment、可选 dataset_id、skip_existing、confirm_changes、confirmation_token、template_names。package 接受 JSON 对象或原始 JSON 字符串；网页发送原始字符串以保留超过 JavaScript 精确范围的整数。请求体最大 16 MiB。

预览与提交
预览运行实际事务再回滚，不创建数据集、不修改结构或记录；返回差异、统计与 confirmation_token。最终提交携带 token；目标数据或结构已变更时必须重新预览。结构变更需要 confirm_changes，整体事务失败不留下部分写入。
现有目标保留源结构没有声明的字段；修改已有字段区域、KEY、顺序、列表规则或将字段设为忽略等变化列入确认。忽略区域会清除对应已有值。模板重名拒绝提交，可在配置中明确重命名。

兼容性
仅结构不能夹带记录；版本或未知属性不受支持时拒绝导入。若旧数据包含未声明字段，原生包导出会拒绝并提示先补全字段定义，避免静默丢失；常规数据导出仍可用于取出旧数据。文件为明文 JSON，机密是否包含由每次导出明确选择，选择不会沿用上一次。

普通 JSON/JSONL/CSV/XLSX/YAML/TOML 导入也将业务字段 id 与系统记录 ID 分离；新记录由服务生成系统 ID，按目标数据集与逻辑 KEY 匹配现有记录时保留其原系统 ID。映射模板名已属于其他数据集时拒绝提交，不移动或覆盖模板，整个导入事务回滚。

普通记录交换格式

仅数据导出以及普通文件导入支持 JSON、JSONL、CSV、XLSX、YAML（.yaml / .yml）和 TOML。扩展名不区分大小写，文本使用 UTF-8。仅结构、结构与数据的原生包仍使用 JSON。

JSON 和 YAML 支持单个对象或对象数组；YAML 也支持以 --- 分隔的多个文档，各文档必须是对象或对象数组。JSONL 每个非空行是一个对象。三者导出的记录分别使用对象数组、对象数组和逐行对象。嵌套对象沿用普通 JSON 导入规则，展开为点分隔的源字段，数组保留为字段值，再进入字段映射与预检流程。

TOML 导出采用 [[records]] 数组表；导入支持这种文件或单个根表。仅当根表只有 records 且其值为数组时，将它作为批量记录容器，其余根表按单条记录处理。日期/时间导入为字符串。TOML 不支持 null，导出遇到任何层级的 null 或超出 64 位有符号范围的整数时会报错，不会丢弃字段或更改类型；此时选择 JSON、JSONL 或 YAML。TOML 的 nan / inf 无法存入 JSON 数据模型，导入会拒绝。

记录节点与工作表选择

文件和文本导入均可填写“记录节点”，在展平字段之前选出记录集合。留空沿用默认根节点规则；$ 明确选择原始根节点。支持点分隔路径（private_key.keys）、数字数组下标（groups.0.items）、可选的 $. 前缀，以及 JSON Pointer（/private_key/keys）。含点的键使用 JSON Pointer；其中 / 和 ~ 分别写成 ~1 和 ~0。不执行表达式、不支持通配符。适用于 JSON、JSONL、YAML/YML、TOML；JSONL 的每一行和 YAML 的每一个文档都必须命中该路径。路径不存在、节点不是对象或对象数组、集合为空时拒绝生成批次。原生 JSON 数据集包始终使用完整包。

例如 TOML 的 [[private_key.keys]] 选择 private_key.keys，每个数组表成为一条记录。bundle_ids 这样的数组字段保留原类型，不展开成多条记录；多行字符串保留换行。注释不作为数据导入。导出仍采用普通记录格式，不重建原文件的外层配置、注释或工作簿布局。

XLSX 单工作表沿用直接解析，多工作表先列出工作表名称，明确选择后点击“解析所选文件”。每次导入一张表，不自动合并；空表、失效的表名或无效表头会报错。可直接改选工作表或修改记录节点后重新解析，不必重新选择文件。更改节点、工作表或目标数据集都会清除旧批次和预检结果。离开导入页或封印后清除文件引用与选择。

普通上传 API 的 multipart 字段可附带 node_path 或 sheet；多表且未指定 sheet 时返回 selection_required=true 和 sheets，不返回 batch_id。客户端带 sheet 重新上传后进入通常的映射、预检、提交流程。POST /imports/text 可附带 node_path。

数组索引字段

索引字段允许 JSON 数组，不需要将 bundle_ids 拼成字符串。检索按任一元素匹配，例如 bundle_ids:=com.example.one；包含、前缀、后缀、正则同样按元素计算。多个条件仍是 AND，可分别命中同一数组中的不同元素。空数组不命中任何条件。数组字段在摘要中按实际命中的元素高亮，评分取该条件最佳元素，元素重复不额外加分。

索引字段与逻辑唯一 KEY 是不同设置。推荐以稳定的 id 或 issuer_id + id 作为逻辑 KEY，将 bundle_ids 仅设为索引。若把数组选作逻辑 KEY，现有规则会以整个数组（含顺序）判断相等，不保证数组内每个元素独立唯一。private_key 应设为敏感字段，默认导出不含机密值。

YAML 示例：
- code: "001"
  enabled: false
  count: 0

对应 TOML 示例：
[[records]]
code = "001"
enabled = false
count = 0

YAML 重复键、未知自定义标签、非有限数值及超过解析资源限制的文件会被拒绝；不支持从文件包含或执行外部内容。CSV 表头必须非空且不重复，各行列数必须一致。嵌套字段展开后与点分隔字段重名时拒绝导入，避免覆盖数据；空对象字段保留。空文件或无可映射字段的输入不生成批次。所有普通导入继续遵守每批最多 10000 条记录的限制。仅数据导出保持原有权限与机密字段选择规则。

文本批量录入与文本导出

产品入口：导入工作台的“数据来源”可选上传文件或粘贴文本；导出弹窗的“输出方式”可选下载文件或生成文本。文件与文本共用字段映射、模板、逻辑 KEY 冲突处理、批量预检和确认，不另建一套写入流程。

文本录入：选择目标数据集 → 粘贴原文 → 自动识别或指定 JSON / JSONL / CSV / YAML / TOML → 点击解析 → 核对识别格式、记录数、字段数 → 配置映射 → 预检 → 确认写入。CSV 首行是表头；单列 CSV 必须手动指定。自动识别优先匹配 JSON / JSONL，其他格式存在歧义时要求手动选择，不静默采用其中一种。指定格式后不回退到其他解析器。原生 JSON 数据集包可直接粘贴，仍走原生迁移流程并保留原始整数文本。

长文本框支持纵向调整高度，显示字符数、行数、UTF-8 大小；输入上限 1 MiB，普通记录每批上限 10000 条。空文本、无记录、无字段、语法错误和容量超限不进入下一步。错误显示在文本框旁，保留原文供修改；修改原文或格式会清除旧批次、映射和预检，必须重新解析。解析本身只生成内存批次，不写入记录。离开带草稿的工作台沿用已有放弃变更确认。成功导入、离开工作台或封印时清除文本草稿，不写入本地持久化存储。

文本导出：选择内容、格式、记录范围以及是否包含机密 → 生成文本 → 查看或复制。默认仍不包含机密，不自动复制、不触发下载、不创建导出文件。普通记录支持全部文本格式；仅结构、结构与数据固定 JSON；XLSX 仅支持文件输出。只读文本区保留服务端原文，避免浏览器解析再序列化导致长整数精度丢失。提供复制全部、全选文本、清除文本；复制失败自动全选并提示手动复制。

展示上限 2 MiB，超限时提示缩小范围或主动选择文件，不截断数据、不自动降级下载。修改任何导出选项都会清除旧文本和旧错误，需重新生成；关闭弹窗或封印清除结果，迟到的请求不得重新填充已清空或重新打开的窗口。复制到系统剪贴板后的内容由用户管理，关闭弹窗不承诺清空系统剪贴板。权限和导出审计沿用文件导出规则。

文本 API：POST /imports/text，请求 {"text":"原始文本","format":"auto"}。format 可省略；可选 auto/json/jsonl/csv/yaml/yml/toml。仅管理会话可用。返回 batch_id、format、record_count、source_fields 等批次信息；后续通过已有预检与确认 API 提交。请求体上限 8 MiB（覆盖 JSON 转义开销），解码后的 text 上限 1 MiB。原生包使用原有 transfer API。文本导出复用 GET /datasets/{id}/export，客户端读取响应原文而不保存文件。
