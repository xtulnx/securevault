# 数据模型与多标签

数据模型定义数据集的结构：字段、逻辑 KEY、默认展示和附表规则。同一模型可供多个客户、环境下的数据集引用。为兼容已有数据库、备份和接入程序，存储表名 `shared_schemas`、接口 `/schemas` 及 `schema_id` 等协议标识继续沿用。模型说明只通过管理目录及结构导出提供，不加入接入应用的普通数据集元数据。

数据集实例通过 `schema_id` 引用数据模型，通过 `dataset_environments` 关联多个标签，标签目录沿用 `environments` 表和接口名称。独立客户属性已取消，客户、测试/生产等分类都用标签表达。目录负责业务组织；标签用于分类与筛选，权限始终绑定数据集 ID。

数据模型统一维护主表字段、逻辑唯一 KEY、默认列表配置、记录标识和附表字段，也可保存独立的模型说明（Markdown），记录用途、数据来源、提取步骤或 SQL。同一模型的说明共用；数据集自己的描述仍表示实例差异。说明在独立弹窗中编辑/预览，也可从模型查看页或数据集基本信息查看；仅修改说明不会迁移记录、密文或授权。实例独立保存可选名称、目录、说明、主表和附表记录、导入映射及应用授权。同一个逻辑 KEY 的值可存在于不同实例，导入更新和删除缺失项只作用于目标实例。业务字段 `id` 始终是业务值，新记录使用服务生成的独立系统 ID；已有记录按实例内的 KEY 更新时保留原系统 ID。导入模板名称已被另一数据集使用时拒绝导入，不覆盖或移动原模板。

## 管理操作

在“数据集”页面通过“数据模型”“标签”分别管理。新建或编辑数据集时，可选择已有标签或直接输入新名称，按回车或“添加”加入，也可直接保存尚未确认的输入。标签按名称去重，新名称在数据集保存事务内自动创建；取消或保存失败不会留下临时项。输入新标签时支持用中英文逗号、分号批量拆分；精确选择已有标签时保留其完整名称。普通编辑和原生导入都保留已存标签数组及顺序，不会再次拆分载入的名称。最多关联 64 个标签，每个新名称为 1 至 120 个 Unicode 字符；已有旧标签的原始名称（包括首尾空格）保存时不被改写。管理页支持标签改名、删除，仍被任意数据集引用时不能删除。

筛选标签按交集匹配：D1 带“客户A、测试”，D2 带“客户A、生产”，选“客户A”命中两个数据集，再选“生产”只命中 D2。取消一个标签只移除对应条件，“全部标签”清空条件。检索页与管理页均支持组合筛选，手机使用同样的标签按钮。结构化查询 `env:=生产` 能匹配任一标签。多个标签描述的是同一份数据，不会复制记录，也不会合并不同数据集的导入或授权。

新建数据集时选择数据模型并添加标签；也可先建立独立空结构，首次导入再定义字段。管理列表把目录和数据模型分列，常用操作直接展示。点击标题或记录数进入该数据集的记录，点击模型或字段数默认查看共享模型，再通过“编辑模型”修改结构；“信息”“编辑”“导入”“新增”“附表”“导出”可直接操作。基本信息可调整名称、标签及目录。名称最多 120 个字符，去除首尾空格，可以重名；留空时在界面显示目录末级名称，不会写回目录或数据模型名称。列表、详情及数据集选择器显示实例名称，选择器同时保留目录和标签用于定位，授权与导入仍使用数据集 ID。字段、默认展示及附表结构从数据模型入口编辑，实际附表记录仍在实例内维护。

编辑基本信息时，单独展示当前引用的数据模型、版本与说明摘要，点击详情可直接阅读取数步骤和 SQL。导入页在选择文件前展示目标数据集及数据模型的基本信息，详情以只读弹窗打开，不会清空文件、映射或未保存的名称与标签。原生文件导入新数据集时显示拟新建的实例和独立模型；选择已有目标时分别展示当前目标与文件信息，即使模型同名也不会把文件说明当成目标模型说明。说明只使用已有管理权限读取；加载失败可以重试，封印会清空摘要和详情。

合并旧数据集时，先选择一个目标模型，必要时修改其名称或补齐字段，再点“合并数据集”，手动选择来源实例。目标模型必须包含来源的全部主表和附表字段；不能通过合并悄悄丢弃字段。用途、KEY、名称和展示差异会在预览中列出。合并后实例 ID、记录 ID、标签、目录、说明和应用授权不变，原结构在无人引用时可手动删除。

## 预览与发布

数据模型默认以只读界面打开，包含字段定义、检索展示规则和附表字段。模型描述与数据集描述共用独立弹窗，支持 Markdown 预览和移动端编辑。从查看页保存模型描述时，仅发送说明并通过预览令牌提交；从模型编辑器打开时先保存到本地草稿，随模型一起发布。默认展示字段、顺序、展示形式、记录标识和密度由模型统一配置，检索页的临时密度切换及命中字段前置不改变模型。

数据模型结构修改和合并均先预览，再确认发布。预览运行实际迁移事务并回滚，检验字段解密、转换和附表关联，返回涉及的实例及主表/附表数量，不返回记录值。需要清除字段已有值时，将其显式改为“忽略”；字段重命名通过原字段映射迁移，重命名与现存值冲突、记录 JSON 无法解析、或附表存在目标定义之外的未知值时拒绝迁移，保留原值；字段集合相同但包含显式交换名称映射时仍执行值迁移。

发布在一个事务内更新数据模型定义及所有涉及实例，并同步主表加密区域、检索字段、KEY 和附表关联。任一实例失败则全部回滚。确认令牌由数据密钥签名，绑定请求、结构、标签及记录状态；预览后发生变化时拒绝提交，必须重新预览。版本号是成功结构更新与发布的递增标记，不提供历史版本恢复功能。

旧的单实例编辑、首次导入结构演进和原生数据包导入仍兼容，但不能单独改动被多个实例引用的数据模型定义。需要结构差异时先统一发布；常规数据导入与记录编辑继续独立执行。

## 运行时自动升级

适用于现有 `data/vault/` 保险库布局和密钥封装格式内的旧数据库，不转换更早的不兼容开发数据布局。

使用启动密码启动服务，或在页面首次解锁时，服务自动检查并升级表结构。新增数据模型、标签目录和多标签关联表。数据库版本 4 新增 datasets.name，旧实例默认空名称并继续按目录末级显示；版本 3 新增数据模型 description，旧模型默认空说明；版本 2 会回填旧单环境关联，原有客户名称转为额外标签，并清空旧 customer_id，防止用户移除标签后再次升级又被自动补回。旧 customers 表和 customer_id 列只为读取旧库/旧备份兼容保留，不提供新客户管理入口。旧表字段补齐、附表关联修复和模型回填全部位于同一事务内；任一步失败均回滚，可修复后重新执行。数据库版本高于当前服务支持范围时拒绝启动升级，避免降级写入。

每个旧数据集获得独立模型，不按字段相似度自动合并；旧环境标签原样登记，不从目录推断客户。迁移不修改现存数据集 ID、记录 ID、受保护字段密文、逻辑 KEY 哈希、应用密钥、授权范围或期限。数据集表上的旧结构列作为兼容查询、检索和客户端接口的物化副本，所有结构写入受数据模型定义校验，不能成为独立维护的分支。

完整逻辑备份保存数据集名称、共享引用及全部标签关联和顺序。旧备份缺少 name 时恢复为空名称。读取旧 v1 备份时自动补齐独立模型并把环境、客户名称转为标签。单数据集交换文件携带结构及 environments 标签名称数组，新建导入建立独立模型，不因名称相同而自动共享；后续可手动合并。全量备份恢复与完整密钥轮换仍按原有规则撤销应用凭据，正常运行时升级保留凭据。

## API

| 接口 | 用途 |
| --- | --- |
| `GET /api/catalog` | 数据模型定义和标签目录，仅管理会话 |
| `POST /api/catalog/environments` | 创建标签，参数 `name` |
| `PATCH /api/catalog/{kind}/{id}`、`DELETE /api/catalog/{kind}/{id}` | 改名或删除，kind 为 environments |
| `POST /api/schemas/preview` | 结构创建、修改或手动合并预览 |
| `POST /api/schemas/publish` | 携带预览令牌，事务发布 |
| `DELETE /api/schemas/{id}` | 删除无人引用的结构 |

结构请求包含可选 `schema_id`、`name`、`description`、`definition`、`dataset_ids`。description 保存模型说明原文，更新时省略保留原说明，空字符串表示清空；手动合并省略该字段会保留目标模型说明。说明变化也绑定预览令牌，并通过同一预览/发布流程提交。新建结构需要 `name`；省略 definition 时引用现有结构，或使用第一个来源实例定义。`dataset_ids` 是要加入目标模型的实例；现有引用实例自动纳入影响范围。发布需携带预览返回的 `confirmation_token`。

definition 包含 fields、identity_fields、list_fields、display_config、supplement_fields。主表及附表字段支持 `previous_source_key` 表示重命名。

数据集创建和更新支持 `environment_ids`（引用已有 ID 数组）与 `environment_names`（复用/新建名称数组）。两者可以同时使用，按 ID、名称依次去重；提供任一数组时表示整体替换，空数组清除全部标签，更新时省略两个数组则保留原标签。新数组不能与旧的 environment/environment_id/clear_environment 混用。旧单环境写入保留兼容，表示替换为一个标签，旧清除选项清除全部标签。返回 `environment_ids` 和 `environments` 两个按顺序对应的数组；兼容字段 environment/environment_id 表示第一个标签。

网页、Raycast 和 httpyac 均按完整标签名称精确匹配并对多标签取交集，不拆分或去除已有名称的空格。检索支持 `schema_id`、`environment_id`、旧环境文本参数，以及 `environment_tags`（JSON 字符串数组，按全部满足筛选），与目录及应用授权范围取交集。`/api/client/datasets` 仅在调用者已授权的数据集中返回模型名称和标签，不开放全局标签目录、完整模型定义或其他实例列表。独立 customer_id/customer_name/clear_customer 请求字段及客户管理接口已退出当前功能。


## 验证

```sh
cargo test --locked --manifest-path server/Cargo.toml
npm test
cargo build --locked --manifest-path server/Cargo.toml
python3 samples/scripts/catalog_check.py
```

单元与集成回归覆盖旧库幂等升级、实际加密旧库解锁升级、密文及授权保留、跨实例唯一 KEY 与更新隔离、手动合并、共享字段重命名与加密用途迁移、预览回滚、过期及篡改令牌、部分失败整体回滚、多标签交集筛选与引用保护，以及新旧逻辑备份和原生交换。

复核额外覆盖完整业务表在升级前后逐值不变（含密文、失联附表、模板、审计及应用状态）、升级中途失败后的表结构与内容回滚、拒绝未来数据库版本、四个客户/环境组合使用同一业务 id 的批次隔离、同名模板冲突、合并前后应用各授权属性不变，以及未授权实例的详情/导出/主表及附表解密均拒绝访问。

HTTP 检查脚本仅创建 `samples/.build/` 内的临时虚构保险库，退出后清理，不使用现有 `data/`。
