# 安全模型与部署要求

## 认证与授权

解锁不再向所有客户端开放数据库。`POST /api/vault/setup` 与 `POST /api/vault/unlock` 验证主密码后，签发随机管理会话 Cookie（HttpOnly、SameSite=Strict、有效期最多 4 小时）。服务端只保存令牌的 SHA-256；再次解锁轮换会话，封印、超时或进程退出后旧令牌失效。脚本调用管理 API 必须保存并发送 Cookie。启动密码仅在内存中打开数据库，不会赋予匿名请求管理权限。

应用必须同时提供 `X-App-Id` 和 `X-App-Key`，仅允许检索、记录详情、数据集导出和敏感字段查看，并继续检查权限、授权数据集、停用状态和有效期。数据集配置、导入、应用管理和封印均仅限管理会话。请求同时提供 Cookie 和应用凭据时，按应用权限处理；错误凭据不会回退到管理会话。敏感应用的查看与 `include_secrets=true` 导出仅包含 secrets 字段，不能获取 hidden 字段；管理会话的导出可包含所有加密字段，应妥善保护下载文件。

主密码失败解锁使用实例级指数退避：首次失败后 2 秒，逐次增加至 64 秒，等待期间返回 429；重启会重置退避。此机制不能阻止拿到数据库和元数据的攻击者离线猜测密码。首次初始化应在可信本机环境完成，同一操作系统账户内的恶意进程不属于可完全隔离的安全边界。

## 网络部署

HTTP 监听地址强制限定为回环地址，不能直接监听 `0.0.0.0` 或网卡地址。远程访问必须使用可信 HTTPS 反向代理，将内部 HTTP 端口留在本机。

远程部署需设置完整的 HTTPS 来源（不带末尾斜杠或路径），例如：

```sh
SECUREVAULT_PUBLIC_ORIGIN=https://vault.example.com ./securevault --addr 127.0.0.1:4173
```

反向代理必须保留外部 Host/Origin，外部 Host 必须与该配置一致。此配置使管理 Cookie 带 Secure；浏览器应通过配置的 HTTPS 地址使用服务。禁止信任客户端提交的转发头，禁止同时公开内部端口，客户端不得绕过证书校验。服务端拒绝非白名单 Host、不同来源 Origin 和跨站 Fetch Metadata，阻断常见 CSRF 与 DNS 重绑定入口。没有该配置时仅支持 `127.0.0.1`、`localhost`、`::1`。

返回内容包含 CSP、禁止嵌入、nosniff 与 no-referrer；所有 API 响应使用 `Cache-Control: no-store`。CSP 阻止内联脚本，样式仍允许内联以兼容现有界面。

## 存储与密钥

数据库使用 SQLCipher，敏感与隐藏字段另用 AES-256-GCM。数据库、字段加密与逻辑 KEY HMAC 分别使用独立随机的 256 位密钥，不再从主密码直接派生。主密码通过 Argon2id（64 MiB、3 次、并行度 1）与 HKDF 派生封装密钥，只负责加密这三把数据密钥。

封装使用 AES-256-GCM，每次生成新的 16 字节盐和 12 字节 nonce。AAD 认证格式版本、数据库 UUID、封装代次、KDF 名称及参数；格式和参数严格校验，拒绝修改参数导致的资源消耗攻击。元数据不保存主密码、明文数据密钥或独立密码校验值，解封的认证标签用于验证主密码。主密码最少 12 个 Unicode 字符、最多 1024 个 UTF-8 字节，建议使用密码管理器生成的长随机密码。

这是全新的未发布数据格式，不提供旧开发数据库迁移。新数据保存在 `data/vault/`。发现旧布局会拒绝启动，必须使用新的数据目录，不能仅移动旧文件来冒充新格式。

### 主密码更换

在已解锁界面的“安全设置”主窗口输入当前密码、新密码和确认密码。`POST /api/vault/password` 只接受管理会话，并在持有运行时锁时再次验证会话和当前主密码；当前密码错误与解锁共享指数退避。相同密码、确认不匹配及长度不合规会拒绝。

操作为相同数据密钥生成新的密钥封装，不修改业务数据、密文、逻辑 KEY 或应用授权。新封装先使用新密码解封自检，再写入同目录的 0600 临时文件，执行文件 fsync 后原子 rename 替换元数据，并执行父目录 fsync。rename 前失败不改变旧密码；rename 后视为已提交，目录同步失败通过 `durability_warning` 返回，不能误报“未修改”。成功后清除内存密钥和暂存导入，撤销全部管理会话、退出常驻状态，要求用新密码解锁。审计写入失败单独通过 `audit_warning` 返回，不撤回已经提交的密码变更。网络连接中断时，客户端应通过重新解锁确认密码状态，不应盲目重复提交。

首次初始化在私有临时目录内完成数据库和封装写入、同步，然后原子发布整个 `vault/` 目录，避免可见的不完整初始化。崩溃遗留的临时目录只包含加密数据，不会被作为有效数据库打开。缺失数据库时解锁会拒绝，不会悄悄创建空库。每个数据目录通过进程生命周期的独占文件锁禁止多实例同时写入。

密码更换不等于完整数据密钥轮换。攻击者若已取得旧封装及旧密码，可以恢复原数据密钥；因为常规改密码保留数据密钥，攻击者仍可能解密后续获得的同密钥数据库。旧数据库和备份也不会失效。疑似数据密钥泄漏时需要生成新数据密钥并完整重加密，可使用下方离线 CLI 完成。使用启动密码时，外部服务配置也必须同步更新，否则下次启动会因旧密码失效而失败。

### 离线完整数据密钥轮换

完整轮换会重新生成数据库、敏感字段、逻辑 KEY 三把独立随机密钥，并使用新的主密码封装。它适合计划性的重加密维护及怀疑数据密钥泄漏后的处置：需要停服、完整扫描数据库和额外磁盘空间，运行时间随数据库大小和加密字段数量增长，不适合在网页请求中执行。

1. 停止使用源目录的服务，确认主机与操作系统账户可信，准备足够的本地磁盘空间。新库与 VACUUM 临时文件可能同时存在，保守预留至少源库大小两倍的额外空间（不含备份）。
2. 在可信终端运行以下命令。目标父目录必须已存在，目标目录必须不存在，不能位于源目录内部。默认从终端隐藏输入当前密码、新密码和确认密码；新密码必须不同。

   ```sh
   ./securevault rotate-keys --data-dir ./data --output-dir ./data-rotated
   ```

3. 成功后将服务配置切换到新目录，更新外部启动密码，启动并验证检索、敏感字段与业务集成：

   ```sh
   ./securevault --data-dir ./data-rotated
   ```

4. 所有应用均被停用，旧凭据的哈希被替换；在新库管理界面为仍需使用的应用重新轮换凭据、分发新凭据并启用。仅重新启用不能恢复旧凭据。管理会话随服务停止失效。
5. 在验证和新的备份完成后，按管理员的保留策略处理旧目录、旧封装、旧备份和崩溃临时目录。工具保留原目录，不自动删除或声称实现磁盘安全擦除。

参数支持 `-d`（`--data-dir`）、`-o`（`--output-dir`）、`-h`（`--help`）；自动化可加 `-s` / `--passwords-stdin`，从标准输入提供 JSON 对象，严格包含 `current_password`、`new_password`、`confirm_password` 三项。不要将密码写在命令行参数、shell 历史或脚本源码中。CLI 不使用 `SECUREVAULT_PASSWORD` 等启动环境变量，不监听 HTTP。

源目录与新目录共享服务的独占锁机制，源服务未停会拒绝操作。通过 [SQLCipher 的 `sqlcipher_export()`](https://www.zetetic.net/sqlcipher/sqlcipher-api/#sqlcipher_export) 将完整 schema 与数据直接复制到新密钥加密的临时库，不生成明文数据库、JSON 或 CSV 文件，SQL 临时存储限制在内存；显式保留 `user_version` 与 `application_id`。逐条解密并重加密所有 hidden/secrets 字段，重新生成 nonce，并按完整字段值重算 HMAC 身份索引。记录 ID、重复关联、过期状态、更新时间、数据集配置、导入模板和既有审计记录保留，新增轮换审计事件；应用凭据按上述规则撤销。

提交前检查 SQLCipher 页认证、SQLite 完整性、外键与各业务表数量，关闭并重新打开新库，逐条比对落盘的敏感内容并验证新 HMAC。随后同步数据库、封装与目录，使用 macOS/Linux 的原子“不覆盖”目录重命名一次发布完整新目录。发布前失败清理本次临时目录，源库保持原样；进程被强制终止时可能留下 `.vault-rotation-*` 加密临时目录，服务不会读取它，应由管理员在确认无轮换进程后处理。发布后父目录 fsync 失败报告“已发布但持久化警告”，不能把它当作未提交。

服务不会自动切换目录。成功命令输出与新目录中的完整 `vault/` 都需确认；终端连接中断时先检查目标目录，并使用新密码验证，勿覆盖现有结果。该发布机制仅支持 macOS/Linux 本地文件系统，并要求目录归可信管理员控制；同一操作系统账户的恶意进程能绕过应用锁。

完整轮换使旧数据密钥无法解密之后的新库，但无法撤销已泄露的历史数据或旧备份。如果原主机仍被控制，攻击者仍可获取新密钥或新密码，应先消除主机入侵。轮换后的首次备份应同时保存新的数据库与密钥封装，旧备份不能与新封装混用。

原子性和同步保证以本项目发布支持的 macOS/Linux 本地文件系统为目标；不支持多进程共享同一库或网络文件系统部署。其他平台的目录持久化保证需要独立验证。
Unix 数据目录设为 0700，封装文件设为 0600。目录权限覆盖数据库及日志文件的访问边界。主密码请求和主要密钥缓冲区退出作用域时清零；后台每秒检查普通会话的 30 分钟空闲与 4 小时总时限，主动丢弃密钥。启动密码的常驻模式允许应用持续使用，管理会话仍需显式解锁。

暂存导入数据仅在内存中保存，保留最近 8 个批次、每批最多 10000 行、最长 1 小时，封印时清除。XLSX 限制 1024 个 ZIP 项和 64 MiB 声明解压大小；HTTP 请求沿用 Axum 默认体积限制。复杂恶意解析输入及大数据库检索仍可能消耗资源，远程代理应另设请求限速、大小和超时。

## 展示与导出

数据集逻辑 KEY 与列表格式使用 HTML 转义，服务端校验 schema 字段与列表格式枚举，CSP 提供额外保护。CSV 对可能触发电子表格公式的单元格和列名添加前导单引号；因此 CSV 下载可能对这些文本增加一个字符。JSON 保留原数据，XLSX 使用文本单元格。

`normal`（普通字段）随 SQLCipher 数据库保存，详情 API 单独返回 `normal`，检索结果、匹配范围与 `search_blob` 均排除这些字段；常规导出包含其值。普通字段不是敏感字段，拥有记录读取权限的应用可在详情中访问。`ignore`（忽略字段）只保留 Schema 定义，导入值不持久化，不展示或导出，也不能作为逻辑 KEY；修改已有字段为忽略会删除其公开或加密存储值。导入上传的临时批次仍按既有机制仅驻留内存。上述规则适用于首次导入、后续导入、Schema 编辑和导入时的 Schema 演进。

封印清除列表与已展示敏感信息的 DOM，弹窗关闭清除敏感值。30 秒临时查看是界面时限，无法撤回客户端已经复制、截图、下载或接收的内容。JavaScript 对象、解析结果和导出响应不保证全部物理清零；系统交换空间、崩溃转储、备份与已登录设备的保护仍由部署环境负责。

## 全量逻辑备份

离线 `backup` / `restore` 使用独立密码保护的标准 age + gzip + JSONL，包含全部受保护业务内容，不包含原主密码、数据库密钥或应用凭据哈希。可以由标准工具独立解密；解密后的文件须按机密材料管理。恢复生成新密钥，默认停用应用并撤销旧凭据，校验通过后只发布新目录。格式、版本兼容、安全边界与操作方法见 [备份恢复说明](BACKUP_FORMAT.md)。

## 验证

```sh
cargo test --manifest-path server/Cargo.toml
cargo build --release --manifest-path server/Cargo.toml
python3 samples/scripts/security_check.py
python3 samples/scripts/rotation_check.py
```

安全回归脚本在 `samples/.build/` 新建临时数据库，验证 18 组完整演示功能，以及匿名访问、伪造管理标记、应用管理越权、Cookie/应用权限优先级、Host/Origin、会话轮换、解锁限速、schema 注入与 CSV 公式防护；不读取或改写正式 `data/` 或现有演示库。Rust 测试另外验证封装认证及篡改拒绝、密码更换后数据密钥不变、提交前错误保留旧文件、文件权限、单实例锁、会话超时与既有检索、XLSX 功能。安全回归还覆盖主密码更换的当前密码复验、限速、管理权限、旧密码失效、数据和应用授权保持，以及重启后使用新密码恢复。

这些检查不是完整渗透测试或第三方安全认证。依赖漏洞数据库扫描、真实 HTTPS 部署、持续审计日志、备份恢复和操作系统加固应作为生产上线检查的一部分。

完整轮换回归另外覆盖三把密钥均变化、旧数据库/字段密钥失效、隐藏字段与嵌套身份索引、重复/过期标记、源文件不变、损坏字段拒绝发布、原子发布禁止覆盖；CLI 回归在独立临时目录验证 8 个数据集、98 条记录及所有加密字段导出一致、重启成功和旧应用凭据失效，同时验证终端输入不回显、Unicode 密码与 Ctrl-C 取消后的终端恢复。
